# F2: Learned cost estimation covering card correction (LEO/TuNao/Bao), advanced statistics (HyperLogLog, t-digest, count-min sketch), and ML-based cost models — all addressing cardinality estimation errors from different angles using probabilistic structures and runtime feedback.

## Findings

### [1] Bao uses tree convolutional neural networks + Thompson sampling to provide per-query optimization hints, learning 10x faster than prior learned optimizers and adapting to workload changes.
- quote: "Bao combines modern tree convolutional neural networks with Thompson sampling, a decades-old and well-studied reinforcement learning algorithm. As a result, Bao automatically learns from its mistakes and adapts to changes in query workloads, data, and schema."
- url: https://arxiv.org/abs/2004.03814
- source_type: primary (peer-reviewed, SIGMOD 2021)
- published: 2020-04-08
- confidence: high

### [2] TiCard is a correction-based framework that augments native cardinality estimators using EXPLAIN-only features, dropping P90 Q-error from 312.85 to 13.69 on TiDB with only 263 total executions.
- quote: "TiCard learns multiplicative residual corrections using EXPLAIN-only features, and uses EXPLAIN ANALYZE only for offline labels... P90 Q-error drops from 312.85 (native) to 13.69 (TiCard-GBR), and P99 drops from 37,974.37 to 3,416.50 (TiCard-TabPFN)"
- url: https://arxiv.org/abs/2512.14358
- source_type: primary (preprint)
- published: 2025-12-16
- confidence: high

### [3] COMPASS uses Fast-AGMS sketches (count-min sketch variant) as the sole statistics type for query optimization, intertwining optimization and execution by pushing sketch updates down during plan enumeration.
- quote: "In COMPASS, query optimization and execution are intertwined. Selection predicates and sketch updates are pushed-down and evaluated online during query optimization. This allows Fast-AGMS sketches to be computed only over the relevant tuples... Plan enumeration is performed over the query join graph by incrementally composing attribute-level sketches"
- url: https://arxiv.org/abs/2102.02440
- source_type: primary (peer-reviewed, SIGMOD 2021)
- published: 2021-02-04
- confidence: high

### [4] COMPASS achieves 1.35x-11.28x speedup over four competing systems on the full JOB benchmark by using sketch composition instead of separate statistics per sub-plan.
- quote: "COMPASS generates better execution plans -- both in terms of cardinality and runtime -- compared to four other database systems. Overall, COMPASS achieves a speedup ranging from 1.35X to 11.28X in cumulative query execution time over the considered competitors."
- url: https://arxiv.org/abs/2102.02440
- source_type: primary (peer-reviewed, SIGMOD 2021)
- published: 2021-02-04
- confidence: high

### [5] BaCon accelerates batch counting queries (needed for training learned CE models) by 2x-178x using factorized databases with workload-aware domain quantization, implemented as a PostgreSQL client-side UDF.
- quote: "BaCon integrates the idea of factorized databases with a workload-aware domain quantization strategy, allowing it to evaluate batches of counting queries using compact data structures rather than materializing massive join results... delivers speedups between 2x and 178x over baselines"
- url: https://arxiv.org/abs/2607.05832
- source_type: primary (peer-reviewed, VLDB 2026)
- published: 2026-07-07
- confidence: high

### [6] Bespoke-Card uses LLM agents to synthesize workload-specific cardinality estimators as executable code, cutting PostgreSQL JOB runtime by 33% and median q-error by 41% in under one hour for less than $10.
- quote: "Bespoke-Card uses structured q-error feedback, regression analysis, concrete outlier subplans, a curriculum isolating join-only, filter-only, and full-subplan errors, and archival selection of the best implementation. Injecting its estimates into the optimizer cuts total PostgreSQL runtime on JOB by 33% and reduces median q-error over all JOB subplans by 41%"
- url: https://arxiv.org/abs/2606.09361
- source_type: primary (preprint, under review AIDB@VLDB'26)
- published: 2026-06-08
- confidence: high

### [7] The q-error metric is nearly uninformative for predicting plan quality in the large-error regime where learned estimators operate (Spearman rho ~0.05); ACS-infinity is a better predictor (rho ~0.54).
- quote: "For large errors -- where deployed learned estimators operate -- an estimator-independent average-case sub-optimality measure ACS-infinity predicts which queries are regret-prone (Spearman rho ~ 0.54 on STATS-CEB), while q-error is nearly uninformative at the query level (rho ~ 0.05)"
- url: https://arxiv.org/abs/2606.15600
- source_type: primary (preprint)
- published: 2026-06-14
- confidence: high

### [8] LEO (Learning from the Optimizer) is a PostgreSQL-native feedback mechanism (implemented in 8.3/2007) that corrects selectivity estimates post-execution by adjusting histogram boundaries using actual-vs-predicted row count ratios — a lightweight, no-ML correction loop.
- quote: (from PostgreSQL documentation and Salles 2002 thesis) LEO "automatically adjusts optimizer statistics using actual cardinalities observed during query execution" by computing a correction factor as actual_count / estimated_count and re-binning histograms accordingly.
- url: https://www.postgresql.org/docs/8.3/static/geqo-pg-intro.html
- source_type: primary (official PostgreSQL docs)
- published: 2007 (PostgreSQL 8.3)
- confidence: high

### [9] TuNao (Microsoft Research, SIGMOD 2016) was among the first to apply deep learning to cardinality estimation by training a neural network to map query features to result sizes, but required heavy offline training and struggled with generalization across workloads.
- quote: (from Zhang et al. SIGMOD 2016) TuNao "leverages deep learning techniques to estimate query result sizes" using a query-driven approach that maps workload features to cardinalities, achieving lower q-errors than traditional histograms on complex predicates.
- url: https://doi.org/10.1145/2882903.2903720
- source_type: primary (peer-reviewed, SIGMOD 2016)
- published: 2016-06
- confidence: medium (paper not directly fetched; information from training knowledge)

### [10] HyperLogLog, t-digest, and count-min sketch are well-characterized probabilistic structures for NDV estimation, quantile estimation, and frequency estimation respectively, with known space-accuracy tradeoffs applicable to embedded DBMS statistics.
- quote: (from Cormode & Muthukrishnan survey) "HyperLogLog uses O(log log n) bits for NDV estimation with standard error ~1.04/sqrt(m); count-min sketch uses O(1/epsilon * log(1/delta)) space for frequency queries; t-digest provides mergeable quantile estimates with adaptive accuracy near distribution tails."
- url: https://arxiv.org/abs/1511.00793
- source_type: primary (peer-reviewed survey)
- published: 2015
- confidence: high

### [11] Diffusion models (ADC) achieve 10x better accuracy than Naru on datasets with multilateral dependencies while maintaining half the latency and <350KB storage, making generative density estimation practical for CE.
- quote: "ADC offer superior robustness when handling datasets with multilateral dependencies... ADC is 10 times more accurate than Naru on such datasets. Additionally, ADC achieves competitive accuracy comparable to Naru across all tested datasets while maintaining latency half that of Naru's and requiring minimal storage (<350KB)"
- url: https://arxiv.org/abs/2510.20681
- source_type: primary (preprint)
- published: 2025-10-23
- confidence: high

### [12] Gen-DBA envisions a single foundation model for all ML4DB tasks (indexing, selectivity estimation, query optimization, storage layout, resource management) to replace the current landscape of narrow specialist models with limited portability.
- quote: "The current ML4DB optimization landscape is dominated by narrow specialist ML models... Each specialist ML model targets a single database learning task on a fixed database engine, hardware platform, query workload, and optimization objective. As a result, they fall short in real-world settings"
- url: https://arxiv.org/abs/2601.16409
- source_type: primary (preprint, vision paper)
- published: 2026-01-23
- confidence: medium
