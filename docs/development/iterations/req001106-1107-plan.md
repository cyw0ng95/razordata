### Sub-decisions locked now

- **A. Visibility map**: NOT ADDED in this iteration. The LSM MemStore heap lookup is already amortised O(1) and bitmap would optimistically skip heap; the production-mature path is bitmap on the row ID and only commit to heap when fetch is needed. The REQ text's intent is satisfied by bitmap-then-fetch with no pending-tx check (current code already does this). Documented as deferred under REQ001107.
- **B. Bitmap OR predicate detection**: only top-level OR is detected (no deeper expression-rewrite). AND with mixed columns is handled by composing IndexScans via the bitmap path (each column contributes its own IndexScan child). This matches PostgreSQL's "Bitmap Index Scan" behaviour without introducing a CNF/DNF normaliser.
- **C. IndexOnlyScan row contents**: in razor, an index-only scan returns the secondary-key as a Row with one column (index column name) of `KindText` value. `isCoveringIndex` is checked at planner time; planner is the source of truth, `IndexOnlyScan` is a no-op wrapper that demonstrates the contract.
- **D. EXPLAIN labels**: `BitmapHeapScan`, `IndexOnlyScan` — matches operator type strings, no abbreviation.
