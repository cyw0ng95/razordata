| REQ000700 | EX/eval | **Correlated EXISTS/NOT EXISTS subqueries return wrong results.** `SELECT t.id FROM t WHERE EXISTS (SELECT 1 FROM s WHERE s.g = t.g)` returns all rows instead of filtering. Root cause: `QualifiedName` resolution in `eval.go` lines 47-80 tries `e.Table + "." + e.Name` first, then falls back to `e.Name` — but the fallback matches the wrong table's column when names collide.
